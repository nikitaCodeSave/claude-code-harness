# Провенанс интейка называет измеренное, а не только источник

## Контекст

Ablation (#40) дал результат, который остался только в `evals/results/ABLATION.md` и в devlog:
способность заметить owner-вопрос присутствует и без кита — во всех семи валидных прогонах, — а
контракт добавляет одну форму (поле приоритета, кодированные опции с ценой ошибки, терминальные
исходы вне ledger). Сам shipped-текст при этом продолжал читаться так, будто контракт учит
поведению. Это ровно тот разрыв между заявленным и измеренным, который кит требует закрывать.

## Изменения

**`bootstrap-checklist.md`, провенанс intake.** Добавлена измеренная часть: ablation на одной
фикстуре, 7 валидных прогонов, плечи различались только доступностью файлов кита; вывод — считать
контракт стандартизацией формы, а не обучением поведению, со ссылкой на `evals/results/ABLATION.md`.

**`CHANGELOG.md` → 1.21.3** с тремя блоками: добавленный `evals/`, изменённый провенанс и явный
раздел «не менялось намеренно» — само правило. Одно измерение на одной фикстуре, с операторским
baseline §1–8 в обоих плечах, корректирует **описание** компонента, но не отправляет его на покой.

## Затронутые файлы

- `plugins/harness/references/bootstrap-checklist.md` — провенанс intake (одна вставка)
- `CHANGELOG.md`, оба `plugin.json` → 1.21.3

## Проверка

```bash
./evals/run.sh mech          # 9/9 PASS, включая контрольный half-migrated ledger
```

Версии обоих плагинов в локстепе; битых внутренних ссылок 0; JSON-примеры валидны.

Non-claims: правило intake не менялось — изменилось только то, как кит его описывает. Дельта
измерена при загрязнённом плече baseline (глобальный §1–8 и описание скилла присутствуют в обоих),
поэтому она нижняя оценка, а не итоговая величина; для консюмера без операторского baseline вклад
кита не измерен.
