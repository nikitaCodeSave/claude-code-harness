# Единица работы — спека с оператором, а не свод правил

## Контекст

Претензия оператора: харнесс порождает артефакты, которые мешают работать, а правила, выведенные
из этих артефактов, душат разработку. Два замера **до** правки, оба про кит, а не про гипотезу.

**(1) Кит не запускался там, где нужен больше всего.** В новом проекте скилл отказался
активироваться, и причина лежала в самом файле: тело `SKILL.md` противоречило собственному
`description` — клауза «do NOT use when the operator's own harness already encodes this
discipline» срабатывает у **любого** практикующего оператора, потому что его глобальный
`~/.claude/CLAUDE.md` загружен в каждой сессии. То есть скилл отключал себя ровно в пустых
проектах, ради которых существует. Проект остался без харнесса, а артефакты в нём копились всё
равно.

**(2) Живой проект в 1446 коммитов** (`Greenplun-router-runtime`, тот же, что дал материал для
v1.26.0 и v1.27.0): 816 коммитов (56%) трогают только `.md`/`.json`; активный план вырос до 1585
строк, из которых собственно соглашение — 81 (5%); объявленная секция `## Acceptance` описывала
фазы, закрытые днями раньше, а действующий порог лежал **970 строками ниже**, внутри журнальной
секции; новое ратифицированное владельцем уточнение цели записано **внутрь журнала**, потому что в
файле не было для него места.

Второй замер — это не «план устарел». Это план, который перестал быть соглашением, потому что в
него накапливали фазы и журнал. Отсюда разворот: кит фиксирует не свод правил, а **соглашение** —
пять полей и один исполнимый гейт.

## Изменения

- **`project-docs/workflow.md` перестроен вокруг спеки** (145 → 121 строк, `shipped-by` v1.28.0):
  почему / что / ограничения `[hard]`·`[soft]` как инварианты, а не шаги / **Done when —
  исполнимая команда с ожидаемым результатом** / чего не делаем. Детектор what/why-не-how
  сохранён. Добавлен явный запрет фаз и пошаговых планов в спеке, с замером (2) как причиной.
- **Выброшены** таблица гейтов размера изменения (trivial/small/medium/large со своим набором
  гейтов у каждого) и слой континуити-журналов: `.claude/progress/<slug>.md` в двух формах,
  трёхшаговая процедура закрытия длинной задачи, session-start-ритуал. Носитель континуити —
  **открытая спека**; журнал не мандатится и не заводится там, где проект его не ведёт.
- **Три невыводимые строки удалённых секций сохранены построчно** (то самое условие, которое
  v1.27.0 записала в Audit после чистки в Greenplun): handoff — это утверждение, а не факт;
  реальный вход до фиксации дизайна; эскалация после 2–3 итераций по одной гипотезе.
- **Добавлена дисциплина триажа находок опровергателя.** Рунг производил находки и молчал о том,
  что с ними делать, — это читается как лицензия транслировать их дальше. Теперь: находки приходят
  вперемешку с принятыми остатками и с адверсариальными углами, против которых компонент не
  строился; каждая воспроизводится своим падающим тестом до починки.
- **`SKILL.md`**: клауза самоглушения судит по репозиторию перед глазами, а не по глобальному слою
  оператора, — с замером прямо в файле, чтобы следующая правка её не восстановила. Принцип 8
  переписан с «ADR / progress file / devlog» на спеку и говорит прямо: носитель, который проект не
  ведёт, здесь не заводится.
- **`bootstrap-checklist.md`**: duty-строка CLAUDE.md — спека, не континуити (выживает и в MVH,
  потому что больше ничто в файле не называет, где живёт соглашение); токен Phase 7
  `Continuity` → `Spec[ -]?first`; Phase 8 пишет в носитель, который проект уже ведёт, и коммит —
  **дефолт, а не запасной вариант**; Phase 2c и MVH-примечание синхронизированы с файлом.
- **`audit-checklist.md`**: находка «Continuity duty absent» → «Spec duty absent». Иначе Audit
  ложно срабатывал бы на **корректном** v1.28.0-бутстрапе — класс ошибки, который этот репозиторий
  ловит уже не первый раз.
- **`harness-discipline.md`**: «ongoing long task → progress file» → «work in flight → its open
  spec»; обрамление state-on-disk не тронуто, оно и было сутью.
- **README**: devlog больше не продаётся как дефолтная установка. Кит не мандатит журнал и не
  создаёт его; спутник получает «optional» и свою секцию — для проектов, которые журнал хотят.

## Ошибка по ходу, которую стоит записать

При смене токена Phase 7 греп был сделан **регистрозависимым** с обоснованием, которого замер не
подтверждал: якобы `-c` исключает строчные указатели (`- specs/ — the open agreements`,
«ambiguous spec»). Проверка на трёх формах: ложного прохода, ради которого вводилась
регистрозависимость, **не существует** — его исключает литерал `first` в якоре (pointer-only файл
даёт 0 в обеих формах); а `-c` при этом проваливал `- Spec First:` — обычный перефраз. Возвращено
`-ci`, комментарий переписан под измеренное.

Это ровно рисунок §1 личного baseline, только наоборот: не «негатив не проверен», а
**обоснование не проверено**. Правило прошло бы ревью — оно выглядело аккуратнее строгой формой.

## Проверка

- Свип по имени механизма (`Continuity`, `progress/<slug>`, `change-sizing`, `doc-with-code`,
  `install both`) до и после правки — по требованию `AGENTS.md`. Нашёл **три копии**, которые
  иначе продолжили бы утверждать старое правило, все три — рядом с уже исправленным местом:
  список transcript-grounded duty-строк в `audit-checklist.md` (`… change-sizing · continuity ·
  doc-with-code`) четырьмя строками выше переименованной находки; MVH-строка в комментарии Phase 7
  («only the plan-mode and change-sizing greps apply») — четырьмя абзацами после MVH-примечания,
  которое спека-строку как раз оставляет; и `operator-playbook.md`, всё ещё отправлявший находки
  внешнего аудита в `.claude/progress/<slug>.md`. Повторный свип после правок — чисто. Оставлены
  два хита на `progress/*`: оба описывают, что фактически делает SessionStart-хук плагина devlog,
  а не предписывают носитель.
- **Шесть Phase-7 грепов против шаблона, реально извлечённого из чеклиста** (а не выписанного по
  памяти): `1 1 1 1 1 1`. Якоря в `bootstrap-checklist.md` и `audit-checklist.md` побайтово
  совпадают.
- **Три утверждения о якоре проверены отдельно, потому что публикуются в CHANGELOG**: голый
  `grep -ci spec` на pointer-only файле = 6 (ложный проход подтверждён); якорь на нём = 0;
  `-ciE` на `- Spec First:` = 1, `-cE` = 0 (тот самый ложный провал).
- `./evals/run.sh mech` — M1/M2/M5 зелёные, локстеп 1.28.0. `claude plugin validate .` — passed.
- **`./evals/run.sh sessions` НЕ выполнен.** Все четыре прогона упали на уровне API, не правил:
  s3/s4 — `401 OAuth access token has expired`, s1/s2 —
  `UNKNOWN_CERTIFICATE_VERIFICATION_ERROR`. Контрольный тривиальный промпт через
  `claude --print` виснет без вывода — то есть метод сломан, а не кит (§1: негатив от
  непроверенного метода). Автоиндикаторы раннера при этом напечатали `S3 … НЕТ — FAIL
  (P0-регресс)` — это артефакт пустого вывода, а не регресс. Прогоны, затёршие реальные
  транскрипты прошлого релиза сообщениями об ошибке, откачены к HEAD. Оператор решил пушить
  сейчас, прогоны — следом.

## Открытый вопрос — не для этого релиза

Исходная претензия закрыта не полностью. Полезная нагрузка скилла — ~3191 строка markdown
(`SKILL.md` 210 + references 2682 + project-docs 294), чтобы объяснить принцип «под способной
моделью минимум обвязки даёт максимум продуктивности». v1.28.0 сместила центр тяжести, но не
сократила объём: `bootstrap-checklist.md` 479, `audit-checklist.md` 457,
`native-capabilities.md` 834.

Два собственных замера кита говорят против наивного сокращения, и оба надо учесть до резки:
(а) Phase 2c обоснована замером «skills are a pull channel — сессии, у которых знание лежало
только в плагине, предложили ноль рунгов лестницы», то есть отгрузка файлов в проект нужна;
(б) удаление документа целиком теряет строки-запреты на действие, которых нет больше нигде — на
правке, породившей rule #0, независимый ревьюер вытащил четыре таких утверждения из четырёх уже
прочитанных доков. Резать построчно, с вопросом «где ещё это сказано», и проводить через
независимый свежий контекст.
