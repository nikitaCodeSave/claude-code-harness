# Kit v2: один скилл и три шаблона вместо свода правил

## Контекст

Лаборатория (`~/PROJECTS/Harnesses-Claude`, devlog #144–148) замерила поток разработки
на стенде `pipeline-ab`: скрытые требования владельца, симулированный пользователь, скрытый
оракул, 63 одно-сессионных и 9 многосессионных прогонов. Выводы разошлись с содержимым кита:
plan mode и test-first по умолчанию, свежая сессия для сборки, auto-compact rescue как
основание для субагента. Оператор поставил задачу — harness под большие многосоставные
проекты с лёгким стартом и для новых, и для существующих проектов — и разрешил переписать
кит целиком.

## Решение

- Кит — тонкий установщик измеренного: `SKILL.md` (три пути по состоянию репо, раскладка для
  многосоставных проектов, Pocock по триггеру, permissions, верификация) и три шаблона.
- Удалены `references/` и `project-docs/` с механикой `shipped-by`: свод правил в каждом проекте
  заменён коротким блоком *How we work* в `CLAUDE.md`, каждая строка которого опирается на замер
  (SKILL.md §7). `native-capabilities.md` и `harness-evolution.md` переехали в лабораторию.
- Плагин переименован в `harness`: текущий Claude Code резервирует имена на `claude-` —
  `claude plugin validate` отклонял кит ещё до переписывания.
- Регресс-набор переписан: механика (каждая проверка проверена на падение подложенным дефектом) и
  три сессии — новый большой проект, существующий монорепо (новая фикстура), существующий harness
  с дефектами.

## Открыто

Релиз 2.0.0 (`release.sh`, тег, push) — за оператором. Многомесячное накопление знаний не
моделировалось: правила знаний — страховка, обоснованная на трёх фичах.
