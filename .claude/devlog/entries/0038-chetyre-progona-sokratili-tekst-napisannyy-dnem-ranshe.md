# Четыре прогона сократили текст, написанный днём раньше

## Контекст

v1.21.0 отгрузила intake-контракт и заодно удвоила пункт чеклиста, который его несёт: item 2 вырос
с 47 до 94 строк. Кит наказывает за раздувание не из эстетики — в длинном списке правил соседние
строки читаются хуже. Долг был назван в тот же день и не закрыт, потому что резать по вкусу — это
угадывание: неизвестно, какие строки работают.

Прогоны дали основание. Четыре живые сессии (`claude --print`, свежий контекст, кит по симлинку
через `--add-dir`) вместо рассуждений о том, что модель сделала бы сама.

## Прогоны

**A — Audit против зрелого проекта** (Greenplun, `--permission-mode plan`). Правило «shipped-docs
absent → finding» больше не даёт ложного срабатывания: сессия вынесла отсутствие трёх документов в
раздел «намеренно НЕ пометил находкой», назвав причину — покрытие есть, а `workflow.md` «session
start = git log» противоречит канону проекта. До правки это был бы автоматический finding.

**C — достижимость §11** (тот же проект). Секция читается (перечислены все 12), чек A корректно
молчит. Чек B нашёл реальный незакрытый owner-вопрос — но **вопреки формулировке**: вопрос лежит в
трёх переходах (`features.json.preconditions` → `STATUS.md` → живой план), а проверка требовала
его в самой записи. Аудит по букве отчитался бы «чисто».

**B2 — доставка Phase 5** (чистый Node-проект, read-only вывод ledger). Write-through работает:
`priority` у всех записей, сортировка кладёт первой нужную, intake применён — открытый вопрос
оформлен кодированными опциями с ценой ошибки, отделён от `blocked: true`, выбор за владельцем не
сделан. Phase 7 ledger-грепы PASS/PASS.

**T1 — тест на церемонию** (Python `csv2json` с намеренно жёсткой спецификацией + один
неоднозначный абзац как needle). Ноль вопросов по тому, что README задал; три вопроса — все по
реально неуказанному, включая подсаженный. Ключевое: в пограничном случае (с какой строки считать
`row N`) сессия решила **сама** и записала почему — «прочтения не расходятся в цене, правило 4 не
применяется». Сужающая формулировка работает.

**T2 — аудит проекта без ledger** (Go CLI на 40 строк, два подсаженных дефекта). §11 явно вынесена
в неприменимые: «`features.json` нет, чеклист предписывает пропуск целиком». Ложного срабатывания
нет. Needle-контроль пройден — найдены оба подсаженных дефекта (пин `Claude 3.5 Sonnet` с запретом
многошаговых планов; мёртвое `Glob(./**)`), значит молчание про §11 осознанное. Побочно правило
shipped-docs отработало и на крошечном проекте: «три документа в ad-hoc CLI добавили бы
конкурирующую инструкцию без выигрыша в покрытии».

Невалидный пятый прогон (скилл не загрузился из-за пути вне разрешённых директорий) оказался
полезен: сессия **без** кита изобрела ledger с доказательствами и append-only гардом, но intake —
не изобрела. Слабое, но реальное свидетельство, что контракт не является дефолтом.

## Изменения

**Исправлено по итогам прогонов.** Чек B §11 теперь идёт по указателям (`preconditions`/`notes` →
status/plan/трекер), а не останавливается на записи. Чек A читает обе стороны рассинхрона: поле
обещано ритуалом и отсутствует — или лежит непрочитанным, или стоит на части записей.
Полумиграция названа худшим состоянием, канон требует проставить поле всем разом либо никому.

**Сокращено против прогонов, а не по вкусу.** Item 2: 94 → 72 строки. Вырезано правило «next
condition» для очереди — `blocked_reason` абзацем выше уже несёт «что разблокирует и кто», то есть
это было второе имя существующего поля. Сжаты до одной строки: провенанс, retire-триггер,
write-through, ветка трекера. Осталось то, что прогоны реально упражняли: цена выбирает форму,
молчание в headless не согласие, решение не есть работа, открытый вопрос не блокирует ограниченный
spike. `bootstrap-checklist.md` −21 строка к 1.21.0, `harness-discipline.md` −2.

**Добавлено.** Проверка читаемости трекера стала действием (`gh issue view`, MCP для Jira/Linear);
Bootstrap-шаблон в `SKILL.md` называет intake и `priority`.

Non-claims: сокращение измерено строками, не токенами. Прогонов пять, из них валидных четыре, на
трёх стеках — этого хватает, чтобы отвергнуть два конкретных риска (церемония на однозначной
задаче; ложный finding §11 без ledger), но не чтобы утверждать статистику. Ни один reference не
таксирует каждый turn: `bootstrap-checklist` грузится в Bootstrap, `audit-checklist` — в Audit;
per-turn слоя (`CLAUDE.md` проектов) правки не касались. Механики по-прежнему две строки
(греп Phase 7) — остальное конвенции.
