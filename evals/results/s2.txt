# Claude Code harness audit — httpping

## Summary

Каркас маленький и в основном здоровый: CLAUDE.md на 33 строки, ноль кастомных subagent/hook/skill, никакой оркестрации — форма правильная. Проблемы сосредоточены в двух местах: **слой permissions, где два правила, которым оператор доверяет, не работают** (оба подтверждены машинно), и **`## Working style`, который привязан к снятой с поддержки модели и запрещает сессии планировать**. Третья находка — против самого чеклиста: его drift-детектор даёт 0 на этом репозитории, при том что stale-пин лежит в `CLAUDE.md:22`.

## Findings

**F1 · Deny-правило для `secrets/` мёртвое** — `.claude/settings.json:12`. Вывод Phase 7 дословно: `Write(./secrets/**) is not matched by file permission checks — only Edit(path) rules are`. §10 оценивает мёртвое *deny* как самый дорогой класс дефектов: оператор считает путь огороженным, а он нет. Плюс `Read` не запрещён вообще. Честная оговорка: `./secrets/` в репозитории сейчас нет — это латентный guard, не активная утечка. Фикс: `Edit(./secrets/**)` + `Read(./secrets/**)`.

**F2 · Весь `allow` игнорируется — workspace не доверенный.** `Ignoring 6 permissions.allow entries … this workspace has not been trusted`. То есть каждая сессия спрашивает разрешение на `go build`/`go test`/`go vet` — на собственные критические команды проекта. Ровно тот случай, ради которого §10 требует второй паттерн в grep: без него непроверенный workspace рапортует «чисто», пока все правила инертны.

**F3 · `CLAUDE.md:22-23` пинит поведение к Claude 3.5 Sonnet и запрещает планировать.** Два дефекта в одной строке: §1 — поведенческая привязка к релизу (не provenance, которое надо сохранять, а живая инструкция); §5 — «модель не умеет X», где модель умеет. «Avoid multi-step plans» подавляет plan mode; инструкция самоопровергается в этой же сессии. Рекомендация — **удалить обе строки, а не «разверсионить»**: под любой актуальной моделью остаточный совет просто неверен, сохранять под ним нечего.

**F4 · Drift-детектор из чеклиста слеп к пину в этом репозитории.** Канонический regex дал 0 хитов. Needle-тест на заведомо присутствующей игле:
```
$ grep -nE "Sonnet [0-9]|Opus [0-9]" CLAUDE.md   → exit=1 (слеп)
$ grep -n "Sonnet" CLAUDE.md
22:- This project is tuned for Claude 3.5 Sonnet — ...
```
Причина: regex ловит только форму «имя-затем-версия» (`Sonnet 4`), а старый нейминг — «версия-затем-имя» (`Claude 3.5 Sonnet`). Все до-4 пины невидимы ему в любом проекте. Это находка **против кита**, не против httpping — исправленный regex в отчёте, отправлять отдельным изменением в `audit-checklist.md` §1.

**F5 · `Glob(./**)` в allow — no-op форма.** Честный статус: машинно *не* подтверждено, потому что предупреждения по allow подавлены, пока держится F2. Подтвердится при повторном прогоне Phase 7 после фикса доверия. Слепые зоны проверил руками: `Grep(` в settings нет, опечаток в именах инструментов нет.

**F6 · Оракул зелёный, и эта зелень ничего не значит.** Весь тест-сьют — `TestPlaceholder`, проверяющий `1+1 != 2`. Он не может упасть ни от какого изменения `httpping` и вдобавок не table-driven, вопреки `CLAUDE.md:15`. Сегодня приемлемо как честная заглушка (поведения ещё нет), но первая же реальная функция обязана принести с собой table-driven тест.

**F7 · `go` не установлен — названный оракул не запускается на этой машине.** `command -v go` → пусто. **Я не смог прогнать оракул**, поэтому «зелень» в F6 выведена из чтения теста, а не из выполнения. Не решаю за вас, дефект это проекта или окружения.

**F8 · Continuity duty отсутствует в CLAUDE.md** — anchored grep даёт 0, `.claude/devlog/` нет, в истории один коммит. Слабейший пункт отчёта, и я говорю это прямо: проект сам себя описывает как ad-hoc, а глобальный baseline §6 несёт обязанность слоем выше. Чеклист такую защиту через объединение слоёв отвергает, но лечение здесь — три строки, а не секция.
